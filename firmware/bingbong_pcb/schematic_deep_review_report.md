## Executive Verdict

The schematic is not ready for fabrication or reliable bring-up. The BG95 core net connections are better than the first coordinate-based pass suggested: power, ground, main antenna, main UART, and SIM pins are connected to the correct U2 pins in the KiCad netlist. However, there are still several board-level blockers.

Cleanup pass 1 completed on 2026-06-06:
- Removed `C19` and `C20` from the schematic USB D+ branch. Current netlist: `/USB D+` includes `J2.A6`, `J2.B6`, `R17.1`, and `U5.1`; `C19`/`C20` are absent.
- Moved U3 `DIR1` from `+3.3V` to `+1.8V` / `VCCA`. Current netlist: U3 pin 10 `DIR1` and pin 7 `VCCA` are on `+1.8V`.
- KiCad ERC now reports 43 violations, mostly pre-existing symbol pin-type/no-connect/power-driver cleanup items.

Cleanup pass 2 completed on 2026-06-06:
- Replaced Q1's schematic symbol mapping with SMMBT2222-compatible SOT-23 numbering: pin 1 `B`, pin 2 `E`, pin 3 `C`.
- Set Q1's schematic value/datasheet/description to the exact BOM intent: `SMMBT2222ALT3G` and the Onsemi MMBT/SMMBT2222 datasheet.
- Current netlist: `Q1.1 B -> R1`, `Q1.2 E -> GND`, `Q1.3 C -> U2.15 PWRKEY`.
- KiCad ERC still reports 43 violations, with no Q1-specific ERC hit. The PCB layout still needs synchronization from the updated schematic, or an equivalent manual Q1 pad-net update, before fabrication output.

Cleanup pass 3 completed on 2026-06-06:
- Restored `TH1` as the external battery NTC connection and changed its footprint to `Connector_JST:JST_PH_B2B-PH-K_1x02_P2.00mm_Vertical`.
- Added `R24 = 10k` as a DNP onboard SMD fallback in parallel with `TH1`. Populate `R24` only when no real battery thermistor is installed.
- Added the MCP73871 datasheet/description metadata to U8.
- Current netlist: `U8.5 THERM -> TH1.1 / R24.2`; `TH1.2 / R24.1 -> GND`.
- KiCad ERC still reports 43 violations, with no THERM/TH1/R24-specific ERC hit. The PCB layout still needs synchronization from the updated schematic before fabrication output.

The most severe remaining confirmed issues are:
- The 3.3 V system rail is generated by a buck converter from a single-cell battery-backed rail, so it cannot remain 3.3 V across normal Li-ion discharge.
- The R1200 boost support parts/control have electrical margin issues: CE can be driven above VDD when switched off, and L2 is grossly under-rated.

## Confirmed Good / Refuted Concerns

These were suspicious in a manual coordinate parse, but KiCad netlist export shows they are connected correctly:

- BG95 `VBAT_BB` pins 32/33 and `VBAT_RF` pins 52/53 all connect to `/VBAT`.
- All BG95 GND pins connect to `GND`.
- Main antenna connector `J3.1` connects to U2 pin 60 `ANT_MAIN`.
- BG95 main UART is used: U2 pin 34 `MAIN_RXD` -> `/BG95 RX` -> U3 pin 9 `A2`; U2 pin 35 `MAIN_TXD` -> `/BG95 TX` -> U3 pin 8 `A1`.
- SIM is on the real USIM pins: U2 pin 43 `USIM_VDD` -> J7 C1; U2 pin 44 `USIM_RST` -> J7 C2; U2 pin 45 `USIM_DATA` -> J7 C7; U2 pin 46 `USIM_CLK` -> J7 C3; U2 pin 47 `USIM_GND` -> GND.
- MCP73871 basic power path is not reversed: U8 pins 18/19 `IN` are on `+5V`; pins 1/20 `OUT` feed `/SYS LOAD`; pins 14/15/16 `VBAT/VBAT_SENSE` are on `/VBAT`; pins 10/11/21 `VSS/EP` are on GND.
- USB-C SuperSpeed/SBU pins are no-connect, not shorted to power/ground. USB CC1/CC2 each have 5.1 kOhm Rd to GND.

## Critical Findings

### C1. USB D+ was loaded by 0.1 uF and 22 uF to GND - fixed in schematic

Original evidence:
- Net `/USB D+`: `C19.1`, `C20.1`, `J2.A6`, `J2.B6`, `R17.1`, `U5.1`.
- `C19` BOM value is 0.1 uF and is populated.
- `C20` BOM value is 22 uF and is populated.
- Both capacitor pin 2 nodes are on `GND`.

Current status:
- Fixed in `bingbong.kicad_sch` on 2026-06-06.
- Current `review_netlist.xml` no longer contains components `C19` or `C20`.
- Current `/USB D+` net contains `J2.A6`, `J2.B6`, `R17.1`, and `U5.1`.
- PCB layout still needs an update from schematic to remove the corresponding footprints/pads before fabrication output.

Why this matters:
- USB D+/D- are high-speed signal lines and should only see very low parasitic capacitance. TI's USB ESD part is specified around sub-pF IO capacitance; nF/uF loading is not remotely acceptable.

Impact:
- USB data will likely fail enumeration entirely.
- This also explains why USB-related behavior may be impossible to debug on hardware.

Fix:
- Done in schematic: removed `C19` and `C20` from `/USB D+`.
- If these were intended rail bypass capacitors, move them to the correct power rail.
- Keep U5 as the low-cap ESD element and keep any series resistors/chokes small and USB-appropriate.

### C2. Q1 PWRKEY transistor had a likely symbol/BOM/footprint pinout mismatch - fixed in schematic

Original evidence:
- KiCad netlist: `Q1.1 E -> GND`, `Q1.2 B -> R1`, `Q1.3 C -> U2.15 PWRKEY`.
- Schematic component uses `Transistor_BJT:2N2219`, whose symbol pin 1 is emitter, pin 2 base, pin 3 collector.
- BOM orders `SMMBT2222ALT3G`, a SOT-23 NPN. The Onsemi SMMBT/MMBT2222 family uses SOT-23 pin 1 = base, pin 2 = emitter, pin 3 = collector.
- PCB footprint is a generic/custom SOT-23 with pads numbered 1/2/3; there is no pin remap in the netlist.

Current status:
- Fixed in `bingbong.kicad_sch` on 2026-06-06.
- Q1 now uses `Transistor_BJT:Q_NPN_BEC` with value `SMMBT2222ALT3G`.
- Current `review_netlist.xml`: `Q1.1 B -> R1`, `Q1.2 E -> GND`, `Q1.3 C -> U2.15 PWRKEY`.
- Current ERC has no Q1-specific violation.
- PCB layout still needs update from schematic, or equivalent manual Q1 pad-net synchronization, before fabrication output.

Why this mattered before the schematic fix:
- Before the schematic fix, the transistor base and emitter were likely swapped relative to the schematic intent. PWRKEY may not have been pulled low correctly, or the ESP32 drive could have been connected to the wrong transistor terminal.
- BG95 power-on depends on PWRKEY being pulled low with the timing Quectel specifies.

Fix:
- Done in schematic: replaced/remapped Q1 to match the SMMBT2222 SOT-23 pinout.
- Done in schematic: set the schematic value/datasheet to the exact BOM MPN.
- Still required before fabrication: update the PCB from schematic and physically verify pad 1/2/3 orientation against the datasheet.

### C3. The 3.3 V rail cannot be guaranteed from a single-cell battery using a buck regulator

Evidence:
- U8 `OUT` -> `/SYS LOAD`.
- U6 TPS62172 `VIN`/symbol `VLN` and `EN` both connect to `/SYS LOAD`.
- U6 output net is `+3.3V`.
- In battery mode, MCP73871 `OUT` is battery-backed and can fall below 3.3 V as the Li-ion discharges.

Why this matters:
- TPS62172 is a buck converter. It cannot regulate 3.3 V when its input is near or below 3.3 V.
- ESP32-S2 and the level shifter/logic rails depend on `+3.3V`.

Impact:
- The board may work near full battery and then brown out or behave erratically as the cell discharges.
- A rail named `+3.3V` will actually become a drooping battery-following rail below dropout.

Fix:
- Use a buck-boost regulator for the 3.3 V rail, or implement UVLO/system cutoff above the regulator dropout point.
- If only high-cell-voltage operation is intended, document it and enforce it in hardware.

## High Findings

### H1. R1200 boost inductor L2 is under-rated

Evidence:
- BOM: `L2 = 22 uH`, rated 220 mA, 1.25 ohm DCR.
- Netlist: `L2` is the boost inductor between U1 `VDD` input path and U1 `Lx`.
- R1200 datasheet family allows switch-current levels far above 220 mA; the board's +12 V boost stage cannot be treated as a 220 mA-inductor design.

Impact:
- L2 can saturate, overheat, or produce poor boost behavior.
- The +12 V rail may collapse under display/load transients.

Fix:
- Recalculate peak inductor current at minimum input voltage, maximum +12 V load, efficiency, and ripple.
- Choose a shielded power inductor with saturation current comfortably above calculated peak current, likely in the 1 A class rather than 220 mA.

### H2. R1200 CE can be driven while U1 VDD is off

Evidence:
- U1 pin 1 `CE` connects to `/R1200 CE` from ESP32 U10 pin 12.
- U1 pin 3 `VDD` is behind Q2 on `Net-(Q2-D)`.
- Q2 source is `+3.3V`, drain is U1 input, and Q3 controls Q2 gate.

Why this matters:
- If Q2 is off, U1 VDD is 0 V while ESP32 can still drive CE high. The R1200 CE pin is specified relative to its input/VDD domain, not as an always-3.3-V-tolerant independent logic input.

Fix:
- Drive CE from the switched U1 VDD domain.
- Preferred: pull CE down by default and use an open-drain/transistor stage referenced to `Net-(Q2-D)` so CE never exceeds U1 VDD.

### H3. MCP73871 THERM path depended on an external/unfitted thermistor path - fixed in schematic

Original evidence:
- Netlist: U8 pin 5 `THERM` -> `TH1.2`; `TH1.1` -> GND.
- Production BOM export showed `TH1 = 10k` with a 2.54 mm pin-socket footprint, not a defined onboard NTC/part number.
- MCP73871 uses a THERM input with an internal current source and expects an NTC/fixed network to keep the pin inside the valid temperature window.

Current status:
- Fixed in `bingbong.kicad_sch` on 2026-06-06.
- `TH1` is now an external battery NTC connector using `Connector_JST:JST_PH_B2B-PH-K_1x02_P2.00mm_Vertical`.
- `R24 = 10k` is a DNP `Resistor_SMD:R_0402_1005Metric` fallback in parallel with `TH1`.
- Current `review_netlist.xml`: `U8.5 THERM -> TH1.1 / R24.2`; `TH1.2 / R24.1 -> GND`.
- Current ERC has no THERM/TH1/R24-specific violation.
- PCB layout still needs update from schematic before fabrication output.

Why this mattered before the schematic fix:
- If the external TH1 path was not actually populated or plugged in, THERM was open. The MCP73871 can interpret that as an out-of-range battery-temperature condition and suspend charging.
- Plugging in only a two-wire battery would not satisfy THERM unless a separate thermistor/resistor was also fitted.

Fix:
- Done in schematic: restored the external battery NTC connector and changed it to a vertical JST-PH 2-pin footprint.
- Done in schematic: added `R24 = 10k` DNP in parallel as a no-thermistor fallback.
- Still required before fabrication: update the PCB from schematic and place the JST connector and optional R24 footprint intentionally.
- Assembly rule: do not populate `R24` when the battery NTC is installed, because it would be in parallel with the real thermistor and would distort the temperature measurement.

### H4. MCP73871 configuration should be intentionally reviewed

Evidence:
- `SEL` and `PROG2` are both tied to GND.
- `PROG1` has `R14 = 10 kOhm` to GND.
- `PROG3` has `R15 = 10 kOhm` to GND.
- `~TE` is tied to `+3.3V`.
- `CE` is driven by `/CHARGE EN` from ESP32 with `R16 = 100 kOhm` pulldown.

Review:
- `RPROG1 = 10 kOhm` corresponds to a low charge-current setting in the MCP73871 datasheet electrical table, around 100 mA.
- `SEL/PROG2` low is a USB-current-limited mode choice. That may be correct for USB compliance, but it should be documented.
- `~TE` high disables the safety timer. That is acceptable only if intentional.
- CE defaults disabled until firmware drives `/CHARGE EN`; decide whether the battery should charge before firmware boots.

Fix:
- Confirm target charge current against battery capacity and thermal constraints.
- Decide whether the safety timer should be enabled; if yes, tie `~TE` low.
- Decide whether default charging before firmware boot is required.

### H5. BG95 VBAT rail needs an undervoltage/current-budget review

Evidence:
- U2 pins 32/33/52/53 connect directly to `/VBAT`, shared with battery connector `J4.2`, charger battery pins U8 14/15/16, and bulk/MLCC capacitors.
- Quectel BG95 requires the VBAT rail to remain in its valid operating range and recommends low-ESR bulk plus MLCC close to VBAT pins.
- The current schematic has `C3 = 470 uF`, `C2 = 1 uF`, `C1 = 0.1 uF`, and `C16 = 4.7 uF` on `/VBAT`, but layout proximity and ESR were not reviewed here.

Impact:
- BG95 can brown out as the Li-ion cell approaches the lower end of discharge.
- Cellular current bursts can disturb the charger battery node and charge termination.

Fix:
- Add/confirm hardware UVLO or firmware-controlled modem disable so BG95 cannot operate below its valid VBAT range.
- Confirm the battery can supply BG95 peak current.
- Follow Quectel's VBAT layout guidance: low-impedance path, wide traces/planes, and the recommended capacitor array close to U2 VBAT pins.

### H6. U3 DIR1 high level was tied to the wrong rail - fixed in schematic

Original evidence:
- Netlist: U3 pin 7 `VCCA` -> `+1.8V`; U3 pin 6 `VCCB` -> `+3.3V`.
- U3 pin 10 `DIR1` -> `+3.3V`.
- TI SN74AVC2T245 datasheet states control inputs are referenced to `VCCA`; high on DIR means A-to-B when OE is low.

Current status:
- Fixed in `bingbong.kicad_sch` on 2026-06-06.
- Current `review_netlist.xml` shows U3 pin 10 `DIR1` and U3 pin 7 `VCCA` both on `+1.8V`; U3 pin 6 `VCCB` remains on `+3.3V`.

Review:
- Data mapping is otherwise correct:
  - U2 `MAIN_TXD` -> U3 `A1`; U3 `B1` -> ESP32 RX.
  - ESP32 TX -> U3 `B2`; U3 `A2` -> U2 `MAIN_RXD`.
  - `DIR1` high gives BG95 TX A-to-B; `DIR2` low gives ESP32 TX B-to-A.
- The original issue was that `DIR1` needed to be high in the A-side control domain.

Fix:
- Done in schematic: `DIR1` is now tied to `+1.8V`/`VCCA`, not `+3.3V`.
- Consider pulling `~OE` high to `VCCA` by default and enabling it deliberately after both rails are valid.

### H7. SIM electrical implementation is incomplete

Evidence:
- USIM signal connectivity is correct.
- CR1/CR2/CR3 protect DATA/CLK/RST to GND.
- There is no local capacitor found on `/BG95_VCC` / `USIM_VDD`.
- No series 0 ohm reservations or small shunt filter capacitors were found on RST/CLK/DATA.
- CR schematic value says `PESD5V0F1BLD_315`; BOM orders onsemi `ESD9B5.0ST5G`.

Why this matters:
- Quectel's SIM reference calls out local bypass on USIM_VDD, low-cap ESD, and optional/reserved series/filter passives near the SIM connector.

Fix:
- Rename `/BG95_VCC` to `USIM_VDD` or `BG95_USIM_VDD`; it is not a general modem supply.
- Add 100 nF from USIM_VDD to SIM ground close to J7.
- Add VDD TVS if required by the mechanical exposure/ESD strategy.
- Add 0 ohm series options and optional small shunt capacitors for RST/CLK/DATA.
- Align CR1/CR2/CR3 schematic value, footprint, and BOM to one exact low-capacitance ESD part.

### H8. USB VBUS is a global `+5V` rail with possible backfeed exposure

Evidence:
- Net `+5V`: J2 VBUS pins A4/A9/B4/B9, U8 IN pins 18/19, U8 VPCC, C15, and J6 pin 4.

Impact:
- If J6 or any other board source can drive `+5V`, the board can backfeed USB VBUS into a host.
- If `+5V` is strictly USB input only, the topology may be acceptable, but the global name hides the role.

Fix:
- Rename `+5V` to `USB_VBUS` if it is only an input.
- Add backfeed protection or a load switch if any external connector/regulator can source that rail.

## Medium Findings

### M1. U6 buck support components are marginal

Evidence:
- BOM: `L1 = 2.2 uH`, 500 mA rated.
- TPS62172 is a 500 mA-class buck; TI example component choices use a power inductor with much higher saturation-current margin.
- The only obvious local output cap is `C9 = 10 uF`; the former 22 uF part `C20` was removed from the bad USB D+ branch, so the U6 output-cap requirement still needs deliberate replacement/confirmation.

Fix:
- Select a 2.2 uH inductor with saturation current above calculated peak current.
- Place the proper derated output capacitance close to U6, PGND, and the inductor.

### M2. Q2 BOM and schematic disagree

Evidence:
- Schematic value/datasheet: `FDN340P`.
- BOM: `FDN338P`.

Fix:
- Choose one exact MOSFET and align symbol value, datasheet, footprint, and BOM.
- Recheck RDS(on), current, VGS rating, and package pinout.

### M3. BG95 USB is omitted

Evidence:
- U2 pins 8 `USB_VBUS`, 9 `USB_DP`, 10 `USB_DM` are no-connect.

Review:
- This is acceptable if intentional, but it removes a useful firmware/debug/recovery path.

Fix:
- Either document that BG95 USB is intentionally unused, or route it through 0 ohm options and USB-appropriate ESD.

### M4. VDD_EXT is unused

Evidence:
- U2 pin 29 `VDD_EXT` is no-connect.
- The BG95-side translator rail is instead generated by U7 `+1.8V`.

Review:
- This can be valid. The local 1.8 V LDO provides a rail even when BG95 is off, but that also means the BG95-side signals may be biased before the module is fully alive.

Fix:
- Confirm this is intentional.
- If using BG95 `VDD_EXT`, respect Quectel's current limit and power sequencing.
- If keeping U7, confirm no BG95 input is driven when BG95 VBAT is absent or invalid.

### M5. ESP32 UART uses GPIO matrix pins, not U0RXD/U0TXD

Evidence:
- U10 pin 38 `IO2` -> `/ESP32 RX`.
- U10 pin 39 `IO1` -> `/ESP32 TX`.
- U10 pins 36/37 `RXD0/TXD0` are unconnected.

Review:
- This is valid on ESP32-S2 if firmware configures the UART matrix.

Fix:
- Document the selected pins in firmware and schematic notes.
- Keep boot straps stable: IO0 is used for BOOT; IO45/IO46 are currently unconnected and rely on default/internal behavior.

### M6. ERC is noisy because several symbol pin types are wrong

Evidence:
- ERC reports many `Power output and Power output are connected` errors involving GND pins on U10/U7/U1.
- ERC also reports `power_pin_not_driven` for some rails because no PWR_FLAG or explicit source symbol exists.

Fix:
- Correct library pin electrical types: module GND pins should generally be passive/power_in rather than power_out.
- Add PWR_FLAGs only where they represent real external power sources.
- Re-run ERC until remaining violations are intentional and documented.

## Notes for a Refutation Pass

High-value claims to challenge later:
- Q1 post-fix validation: verify the exact ordered tape/reel MPN, PCB pad-net synchronization, and actual footprint orientation.
- 3.3 V rail dropout: calculate minimum acceptable ESP32/BG95 support behavior over battery discharge.
- MCP73871 THERM post-fix validation: confirm battery pack NTC value/connector pinout and ensure `R24` remains DNP whenever the real NTC is installed.
- R1200 L2: compute actual +12 V load current from the OLED/display and check inductor peak current.
- Removed USB D+ capacitors: determine whether C19/C20 should be deleted from the PCB/BOM or reintroduced on the correct power rail.
